# Change: Generate page breaks instead of hand-authoring them

## Why
Every report added by hand needed `<!--page-->` markers placed manually,
guessing at how much text fits a page. That guessing was wrong often enough
to be the dominant source of bugs in this repo's early history: pages
silently overflowing into a scrollbar, or — the overcorrection — pages left
mostly blank. Adding a report was also fiddly in smaller ways: picking the
right category folder, computing the next `order` value by hand.

## What Changes
- New `scripts/paginate.mjs`: tokenizes a report body (headings, paragraphs,
  lists, tables), estimates each block's rendered height against constants
  calibrated from the live page, and packs blocks into `<!--page-->`-
  delimited pages under a measured budget. Idempotent — safe to re-run.
- New `<!--force-page-->` marker for the rare manual override; unlike plain
  `<!--page-->` (regenerated every run) it's preserved verbatim.
- New `scripts/new-report.mjs`: scaffolds a report file in the right
  category folder with frontmatter filled in and `order` computed
  automatically.
- `npm run paginate` / `npm run new-report` wired up in `package.json`.
- `[...slug].astro`'s page-split regex updated to also recognize
  `<!--force-page-->`.
- New `CONTRIBUTING.md` documenting the add-a-report workflow.

## Impact
- Updated specs: book-reader (page fitting requirement)
- New code: `scripts/paginate.mjs`, `scripts/new-report.mjs`
- Changed code: `package.json`, `src/pages/reports/[...slug].astro`
- All 59 existing reports' page breaks regenerated by the new tool
